# 朔日接入微信客服任务计划

## 已完成

- 新增按 `service code` 延迟创建适配器的注册层，保留头歌原有行为。
- 新增朔日适配器：账号验证、任务列表、ID/TermID 快照、通用收费项、进度归一化和执行结果。
- 默认评分为 `full_score`；默认只本地评分，不提交成绩。只有显式 `submit=True`（或开启提交配置）才允许执行 `test.py` 中的提交语义。
- 微信客服绑定、任务、订单、进度和 worker 调度均携带服务代码；朔日服务开关默认关闭。
- 已加入 fake 客户端/工作流契约测试，避免测试依赖真实朔日、微信或支付。

## 当前不能凭源码完成

生产地址、隔离测试账号、Secret 注入方式、朔日计费单位/价格/退款规则，以及“付款后是否自动提交成绩”的业务授权仍需业务或运维确认。朔日源码也没有可复现的打包元数据，正式上线前必须固定源码 revision 和依赖。

## 灰度顺序

1. 部署朔日运行依赖，但保持服务开关、执行和成绩提交关闭。
2. 用隔离账号验证登录、任务列表和只读 `full_score` 评分。
3. 确认计费/退款后开启测试订单；继续保持提交关闭。
4. 明确付款与 `SUBMIT` 的授权关系，再仅对测试账号开启提交。
5. 通过真实任务、HistoryId/成绩观察、超时和重启恢复验收后，再用管理员服务开关灰度。

## 验收标准

EduCoder 回归测试不变；未付款不能执行；任务使用稳定 ID；密码、Cookie、题包和原始响应不进入客服/管理员输出；提交超时不自动盲重试；服务不可用时任务可安全取消并提示人工处理。
