# 朔日接入缺失信息清单

| 项目 | 已知边界 | 上线前必须补充 |
|---|---|---|
| 生产地址 | `test.py` 只有内网示例 `http://172.18.5.87/srpt` | 正式 URL、端口、网络/VPN、白名单、健康检查 |
| 测试账号 | 源码没有账号文件，运行时输入 | 隔离账号、密码交付/轮换、验证码和可测试任务 |
| 依赖 | `suori` 没有 pyproject、requirements、lock 或 Dockerfile；本地导入提示缺少 `pyzipper` | Python 版本、源码 revision/hash、依赖锁定、运行目录和持久化卷 |
| 计费 | 源码只按任务 ID 选择，没有支付逻辑 | 按任务/关卡等计费单位、单价、最低支付、退款和部分成功规则 |
| 付款与提交 | `test.py` 只有明确 `SUBMIT` 才提交 | 付款后只评分、付款自动提交，还是二次确认；需明确客服文案 |
| 不支持任务 | 源码会拒绝 `ReportMust`、`RequireEnvFile`、已有备份等场景 | 拒绝、转人工或退款策略 |

现有客服通用支付合同的 50 分/单位和最低 100 分只能视为头歌规则，不能自动套用于朔日。当前实现因此按每个朔日任务生成一个通用收费单位，但正式价格确认前不应开启真实扣款。

另需注意：现有绑定表仍按每个客户一条记录设计；同一微信同时绑定头歌和朔日需要先做 `(customer_id, service)` 数据迁移和调度隔离。成绩提交接口无明确幂等键，POST 超时必须人工核对，不能自动重放。
